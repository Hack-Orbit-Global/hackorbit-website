# 15 — SEO Specification

## Objective
Build legitimate, long-term search authority for "Hack Orbit" as an organisation, and naturally establish "Sabarna Barik → Founder of Hack Orbit" — through semantic HTML, structured data, and honest content, never keyword stuffing or fabricated stats. Every public page also targets a Lighthouse SEO score of 100 as a hard engineering requirement (see NFR-SEO-006 in 03-SRS.md).

## Keyword Strategy (natural, non-spammy targets)
- Primary: `Hack Orbit`, `Hack Orbit organisation`, `Hack Orbit open source community`
- Founder-relationship: `Hack Orbit founder`, `Sabarna Barik`, `Sabarna Barik Hack Orbit`
- Secondary/long-tail: `Hack Orbit projects`, `Hack Orbit certificate verification`, `Hack Orbit member profile`, `join Hack Orbit`

These should appear where they'd naturally occur (page titles, headings, founder bio, about copy) — never repeated artificially or stuffed into invisible text.

**Domain-neutrality note**: content and metadata should never frame Hack Orbit as a cybersecurity/hacking-specialist organisation. Where domain examples are given (in About copy, project descriptions, meta text), draw from web development, DevOps, AI/ML, and technology broadly, so search engines and readers correctly understand Hack Orbit as domain-neutral rather than security-niche.

## Page Titles & Meta Descriptions (examples)
| Page | Title | Meta description direction |
|---|---|---|
| Home | Hack Orbit — Open-Source Technology Organisation & Developer Community | What Hack Orbit is, who it's for, one clear CTA |
| About | About Hack Orbit — Mission, Philosophy & Founder | Mission, Build/Contribute/Orbit Together philosophy, founder bio and founding story |
| Projects | Official & Community Projects — Hack Orbit | What's showcased, official vs community distinction |
| Contribute | Contribute to Hack Orbit | How to join and start contributing |
| Profile | {display_name} — Hack Orbit Member {member_id} | Member's public contribution summary |
| Verify | Verify a Hack Orbit Certificate | What verification proves, how to use it |

## URL Structure
Clean, lowercase, hyphenated: `/`, `/about`, `/projects`, `/contribute`, `/profile/{member_id}`, `/verify`, `/join`, `/contact`. No query-string-based canonical content.

## Sitemap & Robots
- `sitemap.xml` generated by `seo/sitemap-generate.js` (a build-time/scheduled Node script, per 25-PROJECT-FOLDER-STRUCTURE.md), including all public marketing pages + all verified member profile pages (queried from Apps Script), excluding auth/admin routes.
- `robots.txt` allows all public routes, disallows `/api/`, `/admin/`, and any authenticated-only paths.

## Canonical URLs
Every public page emits a self-referencing `<link rel="canonical">` to prevent duplicate-content issues (e.g. trailing slash variants).

## Open Graph & Social Metadata
- Every shareable page (home, founder, projects, profiles, certificates-verify result) includes `og:title`, `og:description`, `og:image`, `og:url`, and Twitter Card equivalents.
- Profile OG images can be dynamically generated by a small Vercel Edge Function using an SVG/Satori-based image-generation approach (framework-independent — this works outside Next.js too) showing display name, Member ID, and a headline badge/stat.

## Structured Data (JSON-LD)

**Organization** (site-wide, home/about):
```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Hack Orbit",
  "url": "https://hackorbit.example",
  "founder": { "@type": "Person", "name": "Sabarna Barik" },
  "sameAs": ["<official social/profile URLs>"]
}
```

**Person** (embedded in the About page's founder section):
```json
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Sabarna Barik",
  "jobTitle": "Founder",
  "worksFor": { "@type": "Organization", "name": "Hack Orbit" }
}
```

**WebSite** (home, enabling sitelinks search box eligibility):
```json
{ "@context": "https://schema.org", "@type": "WebSite", "name": "Hack Orbit", "url": "https://hackorbit.example" }
```

**BreadcrumbList**: emitted on nested pages (e.g. Projects → individual project, Profile).

## Founder Relationship (SEO)
- The `Person` schema's `worksFor`/`founder` relationship — embedded within the About page (no dedicated Founder page) — combined with the About page prose and the Organization schema's `founder` field, is the natural, structured-data-first way to establish the relationship — deliberately not reinforced through repeated keyword insertion elsewhere.

## Public Profile SEO
Per 09-PUBLIC-PROFILE-SYSTEM.md: unique titles/descriptions per profile, `Person` schema with `memberOf` pointing to the Hack Orbit `Organization`, indexable by default.

## Performance / Core Web Vitals
- SSG (build-time static HTML) for marketing pages, server-rendered HTML from Vercel Serverless Functions for profile/verify pages — no client-side-only rendering for first paint of SEO-relevant content (see 04-SYSTEM-ARCHITECTURE.md, 22-FRONTEND-ARCHITECTURE.md)
- Image optimisation via pre-processed, correctly-sized, modern-format (WebP/AVIF) assets with explicit `width`/`height` and `srcset` (see 23-PERFORMANCE-SPECIFICATION.md) — no framework image component required
- Target: LCP < 2.5s, CLS < 0.1, INP < 200ms on median mobile (ties to NFR-PERF-001)

## Content Strategy
- About (including its founder section) and Projects pages written as genuine, specific content — no invented statistics; any community numbers shown (member count, project count) must be pulled live from real data, or omitted until real and worth showing.
- Internal linking: Home → About → Projects → Contribute → Join, and Projects → individual profiles of contributors, forming a natural crawlable graph.
